    Cloud (Anthropic) Local (Ollama) Automation

    Two providers, one jawb. Cloud (Anthropic) handles anything you don't route locally and is the fallback when Ollama fails. Local (Ollama) is opt-in per feature — great for routine tasks, keeps tokens off your bill.

    Cloud provider — Anthropic

    Required. Handles everything not routed locally.

    Cloud provider & API key

    Pick which cloud AI runs the analyses. Each provider's key is stored locally in chrome.storage.local — never included in exports.

    ▸ How to get an Anthropic API key
    1. Create an Anthropic account. Go to console.anthropic.com and sign up (or log in). Free to create; you only pay for API usage.
    2. Add credit. Under Settings → Billing → Plans, add a payment method and buy any amount of credits ($5 is more than enough to start). Typical Jawbs use is fractions of a cent per analysis.
    3. Create an API key. Under Settings → API keys, click Create Key, give it a name (e.g. "Jawbs"), and copy the sk-ant-… value. You will not see this key again — copy it now.
    4. Paste it above and click Save key. Run the diagnostic in System → Diagnostic to confirm it works.

    Privacy: the key is stored in your browser only. Nothing except API calls to api.anthropic.com ever leaves your machine.

    Ollama isn't reachable at localhost:11434. Download and run the setup script for your OS:

    The script installs Ollama, sets CORS so this extension can call it, and pulls the recommended model. Click Recheck when done.

    ▸ Manual setup (if the scripts aren't your style)
    1. Install Ollama. Download from ollama.ai/download. macOS installs a menu-bar app; Linux runs as a service.
    2. Allow this extension to call Ollama (CORS). Ollama refuses requests from browser extensions by default. Set OLLAMA_ORIGINS so it accepts them: 
      launchctl setenv OLLAMA_ORIGINS "chrome-extension://*"
# then restart Ollama from the menu bar (macOS)

# Linux / systemd:
sudo systemctl edit ollama
# add:  Environment="OLLAMA_ORIGINS=chrome-extension://*"
sudo systemctl restart ollama

# Windows (PowerShell):
[Environment]::SetEnvironmentVariable("OLLAMA_ORIGINS", "chrome-extension://*", "User")
# then restart Ollama
    3. Pull a capable model. Recommended: qwen2.5:14b-instruct (works well for Fit + Question Prep on a 32 GB machine). Smaller: qwen2.5:7b-instruct. 
      ollama pull qwen2.5:14b-instruct
    4. Enable the local provider above and check which features to route locally. Cover Letter and Tailored Resume stay cloud-only by default — they benefit from the stronger model.

    Cloud remains the automatic fallback on any local failure (model missing, timeout, etc.).
